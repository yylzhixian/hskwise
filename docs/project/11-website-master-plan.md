## 2. 产品结论

### 2.1 一句话定位

HSKWise 是面向海外学习者的路线式 HSK 学习与备考网站，让学习者每次打开网站都知道下一步学什么，并通过短时、沉浸、可互动的课程持续建立中文能力。

### 2.2 核心承诺

用户不需要自己研究大纲、挑选教材或组合练习。HSKWise 应做到：

1. 根据学习目标确定起点和路线。
2. 每次只给出一个清楚的 `Continue` 行动。
3. 用 5-10 分钟完成一个可感知进步的互动课。
4. 自动把错误和遗忘内容安排回后续学习。
5. 用 HSK 标准、课程完成度和能力表现解释进步。

### 2.3 产品不是什么

- 不是教材 PDF、词表和题库的集合页。
- 不是以聊天机器人为首页的 AI 工具。
- 不是先要求用户理解 HSK 2.0 / 3.0 差异的等级目录。
- 不是通用低代码课件编辑器。
- 不是依靠排行榜、体力值或连续打卡惩罚驱动的游戏。
- 不是在早期同时覆盖所有等级、语言、题型和用户角色的平台。

## 3. 从资料和竞品得到的判断

### 3.1 应吸收的能力

| 来源 | 应吸收的能力 | 不直接照搬 |
|---|---|---|
| Brilliant | 一屏一重点、先互动后解释、逐步揭示、即时反馈、概念可视化 | 偏数学/科学的内容结构和营销式页面 |
| Duolingo | 路线节点、短课、明确下一步、检查点、复习回流、低操作成本 | 体力惩罚、过度游戏化、脱离考试目标的碎片练习 |
| SuperTest | 诊断、专项练习、错题本、报告、题目多维标注形成的数据闭环 | 与成熟题库正面比拼题量、版权不清晰的真题依赖 |
| HSK University | Web first、多语言增长、免费课程获客、口语能力差异化 | 赛博朋克视觉、社区冷启动、在核心学习体验前铺开大量 AI 功能 |
| HSK 教材 | 目标、情境、输入、讲练、输出任务、小结的教学节奏 | 原文、原图、原音频、原题和教材专有版式 |
| 官方大纲 | 任务、话题、词汇、汉字、语法和能力标准 | 把大纲目录直接展示成学习路线 |

### 3.2 竞争策略

HSKWise 不以题目数量取胜，而以三层组合取胜：

```text
路线层：下一步明确、目标明确、进度明确
  ↓
课程层：短时沉浸、互动讲解、听说读写结合
  ↓
反馈层：错题归因、间隔复习、能力报告、备考建议
```

早期最重要的是证明前两层形成真实学习体验。AI 口语、模考和个性化推荐只有接入这条主循环后才有价值。

## 4. 目标用户与首发范围

### 4.1 首发核心用户

- 母语不是中文的成年学习者。
- 中文基础为零或接近 HSK 3.0 一级。
- 希望系统学习，并可能在未来参加 HSK 考试。
- 主要使用手机，也会在桌面浏览课程和进度。
- 第一版界面语言使用英语，课程提供汉字、拼音和英语解释。

选择入门用户作为产品验证对象，是因为语音、对话、生词、句型和复习都能在较小内容范围内验证；这不代表长期产品只服务初学者。

### 4.2 后续用户

- HSK 2.0 当前考试备考用户。
- HSK 3.0 二至六级学习者。
- HSKK 口语专项用户。
- 教师和机构用户。

### 4.3 第一版明确不覆盖

- HSK 3.0 七至九级完整课程。
- 完整真题库和大规模模拟题库。
- AI 自动口语评分和 AI 作文批改。
- 教师、班级和机构后台。
- 社区、排行榜和好友系统。
- 原生 iOS / Android App。
- 完整多语言翻译。
- 通用 Course Studio。

## 5. 核心学习体验

### 5.1 路线式主体验

路线是用户的主界面，不是课程目录的装饰。

```text
目标选择
  -> 推荐起点
  -> 路线阶段
  -> 当前节点
  -> 5-10 分钟互动课
  -> 课末反馈
  -> 解锁下一节点 / 安排复习
```

路线由以下节点组成：

- `lesson`：教授一个新概念或完成一个情境任务。
- `practice`：集中练习刚学内容。
- `review`：根据遗忘和错误生成的复习节点。
- `checkpoint`：阶段性综合检查。
- `challenge`：可选的听说或应用任务，首版不影响主线推进。

路线允许有限分支，但首版采用清晰的单主线，避免用户再次面对选择压力。

### 5.2 Brilliant 式课程原则

每门课遵守：

- 一屏只完成一个学习动作，不展示长篇讲义。
- 尽量让用户先观察、选择、拖动、排序或尝试，再给出解释。
- 解释紧跟用户行为，不把答案提前暴露在题目前。
- 内容逐步揭示；汉字、拼音、翻译按教学需要出现，不默认全部堆叠。
- 每 30-60 秒至少有一次有意义的输入或决策。
- 错误反馈说明“为什么”，并允许立即重试。
- 课程结束明确展示学会了什么、哪里需要复习、下一步是什么。

课程不是固定幻灯片播放器。音频、动画和进度服务于学习动作，不建设通用时间轴。

### 5.3 标准课时结构

单课建议包含 6-12 个步骤：

1. `Hook`：情境或问题导入。
2. `Discover`：观察语言现象并做第一次判断。
3. `Explain`：短解释和可视化。
4. `Guided practice`：有提示的练习。
5. `Apply`：在对话、听力或表达中使用。
6. `Check`：无提示检查。
7. `Reflect`：总结、错误提示和下一步。

并非所有课程都机械包含七段，但必须形成“输入 -> 尝试 -> 反馈 -> 应用”的闭环。

### 5.4 首批课程类型

- 拼音与声调：曲线观察、示范音频、听辨、跟读录音、自我比较。
- 对话精读：场景导入、逐句音频、角色区分、点词解释、理解检查、角色扮演。
- 生词学习：从语境发现词义、音形义联系、回忆、听辨、句中应用、错词回流。
- 句型构建：词块排序、替换练习、从提示到独立表达。
- 综合检查：混合听辨、理解和应用，不引入新知识。

## 6. 信息架构

### 6.1 学习者页面

| 路径 | 职责 |
|---|---|
| `/` | 目标优先的产品入口；已登录用户直接进入当前学习路线 |
| `/onboarding` | 目标、基础、学习节奏；不先要求理解标准版本 |
| `/learn` | 产品主页面：当前路线、`Continue`、今日复习和最近进度 |
| `/learn/routes/[routeId]` | 完整路线地图、阶段、节点和检查点 |
| `/lessons/[lessonId]` | 全屏沉浸课程，不显示干扰性的全站导航 |
| `/review` | 到期复习和困难内容 |
| `/practice` | 按技能和知识点进行的可选专项练习 |
| `/mistakes` | 错题、错误原因和再次训练 |
| `/progress` | 路线进度、能力覆盖和检查点表现 |
| `/library/vocabulary` | 辅助词汇查询，不作为每日学习入口 |
| `/settings` | 账户、界面语言、学习偏好和设备会话 |

`/dashboard` 不再单独承担一套重复信息架构；`/learn` 就是学习者回到产品后的首页。

### 6.2 导航原则

- 桌面端主导航：Learn、Review、Practice、Progress。
- 移动端底部导航：Learn、Review、Practice、Me。
- `Continue` 始终是视觉上的第一行动。
- Vocabulary、Courses、标准资料进入 Library 或辅助入口。
- 课程进行中只保留退出、进度、音频和必要设置。

## 7. 首个正式开发纵向切片

### 7.1 目标

先完成一条从进入网站到课程完成、错误回流和路线推进都能运行的最小产品，而不是先完成所有基础设施。

路线名称：`HSK 3.0 Level 1 Starter`

首批四个节点：

1. `认识普通话四声`：拼音与声调讲解课。
2. `第一次打招呼`：原创问候对话精读与跟读课。
3. `记住第一组词`：使用原创对话中的生词学习与练习。
4. `入门检查点`：听辨、词义和对话理解混合检查。

这四个节点必须用三种不同课程实现验证真实差异，不通过一个万能 scene 配置表达。

### 7.2 用户验收脚本

一个首次访问的用户应能：

1. 在 `/` 选择“按 HSK 3.0 系统学习”。
2. 进入 Starter 路线并看到唯一明确的当前节点。
3. 完成四声课程，播放和重播示范音频。
4. 答错听辨题，看到不泄露后续答案的解释并重试。
5. 完成一次跟读录音、回放或明确处理麦克风拒绝。
6. 完成原创问候对话和生词课程。
7. 在检查点看到掌握结果和待复习内容。
8. 刷新页面后保持路线进度。
9. 在 `/review` 再次练习之前答错的内容。
10. 在手机和桌面上使用键盘或触控完成核心路径。

### 7.3 数据与代码边界

首批课程使用本地 TypeScript 数据和窄范围 Zod schema：

```text
src/features/learning-routes/
src/features/courses/runtime/
src/features/courses/pinyin/
src/features/courses/dialogue/
src/features/courses/vocabulary/
src/features/courses/content/hsk3-level-1/
```

- 内容数据必须可序列化，不包含 React、函数、CSS class 或任意脚本。
- React 直接实现课程体验，不先建立通用模板系统。
- 复用现有判题、录音、事件和进度纯逻辑；`ScenePlayer`只作参考，不直接成为学习者课程外壳。
- 访客进度第一阶段可以保存在本地；账户和云同步在纵向切片稳定后接入。
- 正式编写 Next.js 代码前，必须阅读本地 `node_modules/next/dist/docs/` 中对应的 Next.js 16.3 指南。

### 7.4 纵向切片完成标准

- 四个节点可以从头到尾完成。
- 页面不是 Studio 预览，也不依赖 Admin。
- 正文、题目、反馈和素材清单通过 schema 校验。
- 错误能稳定关联到课程、步骤和知识点。
- 音频缺失、失败、自动播放受阻和麦克风拒绝都有明确状态。
- 本地进度刷新后恢复。
- 桌面与移动端通过视觉检查，核心路径可用键盘完成。
- 判题、完成规则、进度恢复有单元测试；核心路径有浏览器测试。

## 8. 内容体系与版权规则

### 8.1 内容事实源

- 官方 HSK 大纲：能力、任务、话题、词汇、汉字和语法范围。
- Complete HSK Vocabulary：词汇主数据，按其 MIT License 保留声明。
- HSKWise 原创教学设计：课程文本、对话、例句、题目、解释和反馈。
- 自制、生成后审核、明确授权或许可证兼容的图片和音频。

### 8.2 教材 OCR 的边界

`docs/textbooks/` 中的已出版教材 OCR 只用于研究：

- 单元节奏和教学顺序。
- 情境导入、讲练结合和任务输出的方法。
- 常见课型和练习形式。
- 不同等级的内容密度。

禁止把教材原文、原题、原图、原音频或教材专有版式直接作为正式课程内容。

### 8.3 占位素材

开发阶段可以使用受限参考素材作为内部占位，但每项必须包含：

```ts
{
  status: 'placeholder',
  rightsStatus: 'restricted-reference',
  mustReplaceBeforePublish: true,
  publishable: false,
  sourceLocator: 'internal reference only'
}
```

- 预览界面必须显示“占位素材，发布前替换”。
- 发布校验必须拒绝任何 `placeholder`、`restricted-reference` 或 `publishable: false` 素材。
- 正文、题目和反馈从第一版起就应原创，不使用教材原文占位。
- 替换后记录创作者、来源、授权方式、生成工具和审核人。

### 8.4 内容生产流程

```text
官方大纲确定目标
  -> 教材仅提供教学方法参考
  -> 编写原创教学设计
  -> 编写原创内容与题目
  -> 教学与语言审核
  -> 素材版权审核
  -> schema / 自动质量检查
  -> 发布
```

AI 可以辅助草拟，但不自动发布；不能把教材原文作为生成输入，后续批量生产前必须加入相似度检查和人工教研审核。

## 9. 学习数据闭环

### 9.1 三层数据必须分离

| 层 | 内容 |
|---|---|
| 内容资产 | 课程、课时、步骤、字词、素材、题目和来源 |
| 路线编排 | 阶段、节点、前置关系、检查点和推荐顺序 |
| 用户状态 | 进度、尝试、错误、掌握度、复习时间和目标 |

同一课程可以被长期能力路线、考试路线和补弱路线复用，不为每条路线复制内容。

### 9.2 最小事件模型

纵向切片开始就记录稳定事件：

- `route.started`
- `lesson.started`
- `step.viewed`
- `audio.played`
- `interaction.submitted`
- `interaction.corrected`
- `lesson.completed`
- `review.completed`
- `checkpoint.completed`

事件至少关联 `routeId`、`lessonId`、`stepId`、`interactionId` 和知识点引用。首版可以本地存储，之后同步到服务端，事件名称和 ID 不应重做。

### 9.3 推荐顺序

1. 已到期复习。
2. 当前路线的下一必学节点。
3. 最近错题关联的补弱内容。
4. 新内容。
5. 可选挑战。

## 10. 技术实施原则

### 10.1 当前技术栈

- Next.js 16.3 App Router、React 19、TypeScript。
- Tailwind CSS、shadcn/ui、lucide-react、Motion。
- Jotai、Jotai Immer；按学习领域拆分 atoms，通过领域 hooks 向组件暴露状态和语义动作。
- Elysia / Eden API。
- Drizzle + Turso/libSQL。
- Zod 作为内容和运行时边界校验。
- Bun 作为包管理和测试运行时。

### 10.2 实施顺序

1. 先完成本地数据驱动的真实学习纵向切片。
2. 再完成 Google 登录、账户、session 和云端进度。
3. 再导入字词主数据并建设复习闭环。
4. 真实课程重复后再提取课程模板。
5. 模板和内容规模稳定后再接课程后台。
6. 学习数据稳定后再做诊断、推荐、模考和 AI。

这会覆盖旧计划中“先完成全部基础设施再看见课程”的顺序。原因是当前最大风险不是数据库是否能建立，而是学习体验是否值得持续使用。

### 10.3 复用与冻结

直接复用或提取：

- 判题和文本规范化纯函数。
- 互动尝试、完成规则和学习事件模型。
- 音频状态处理和跟读录音。
- 进度和错题关联逻辑。
- 稳定 ID、Zod 校验和现有运行时测试。

只作参考：

- `ScenePlayer` 的播放和互动等待实现。
- 结构化互动组件。
- 现有拼音课程蓝图和 sample project。

冻结：

- Course Studio Shell、自由画布、时间轴、Inspector。
- Travels 编辑历史和通用命令层。
- Mock asset library、通用模板选择器和 U2-U4。

首批真实课程稳定前不删除这些实验，也不继续产品化。

## 11. 设计方向

### 11.1 融合原则

整体 UI 明确采用 Brilliant 与 Duolingo 的融合，但两者承担不同职责：

| 维度 | Brilliant 提供 | Duolingo 提供 | HSKWise 的处理 |
|---|---|---|---|
| 页面骨架 | 克制、专注、内容优先、清晰留白 | 路线明确、低操作成本 | 成年学习工具的安静骨架，主行动始终突出 |
| 学习过程 | 一屏一问题、概念可视化、逐步揭示 | 短课、连续反馈、轻量游戏感 | 每屏一个学习动作，反馈明确但不打断思考 |
| 控件触感 | 精确、理性、结构稳定 | 圆润、可按压、状态鲜明 | 适度圆角、清楚边框和轻微按压位移 |
| 进度表达 | 能力与概念掌握 | 路线节点、完成和解锁 | 四声曲线式路线、检查点和掌握状态 |
| 情绪 | 成就来自理解 | 成就来自连续推进 | 奖励真实学习进步，不依赖体力和惩罚 |

建议视觉权重约为 `65% Brilliant + 35% Duolingo`：信息层级、版式和课程画布更接近 Brilliant 的专注感；按钮、节点、反馈和完成动效吸收 Duolingo 的亲和与触感。

### 11.2 HSKWise 视觉识别

HSKWise 不直接复制任何竞品品牌。独有的视觉签名是“声调学习路径”：

- 路线节点由普通话第一至第四声的轮廓变化连接，而不是普通垂直虚线。
- 当前节点像落在声调曲线上的发音锚点；完成后曲线从中性线变为掌握色。
- 声调曲线同时用于拼音教学、音频进度和单元过渡，形成真实的中文学习语义。
- 这项表达集中用在路线与语音课程中，其他页面保持克制，不把曲线变成无意义装饰。

视觉气质：现代、清晰、专注、友好，服务成年学习者；不幼稚，也不堆叠灯笼、书法、龙纹等传统中国风符号。

### 11.3 初始设计 Token

M0 使用以下初始方向，实际实现后通过桌面和移动截图校准：

| Token | 建议值 | 用途 |
|---|---|---|
| `ink` | `#18212F` | 主文字、导航和高对比图形 |
| `paper` | `#F7F9FC` | 页面底色，保持轻盈但不使用奶油色主题 |
| `surface` | `#FFFFFF` | 课程画布和互动表面 |
| `progress` | `#1C7F58` | 完成、继续学习和掌握状态；可配白色文字 |
| `focus` | `#236FD2` | 当前节点、选中、链接和键盘焦点；可配白色文字 |
| `reward` | `#F2B544` | 检查点、阶段完成和有限奖励 |
| `error` | `#B83F4C` | 错误和需要复习；可配白色文字，不承担品牌主色 |

- 不让绿色占据整个界面；中性色承载结构，绿色、蓝色、黄色和红色承担不同语义。
- `reward` 黄色只配 `ink` 深色文字；语义色不能脱离前景色组合单独判断可访问性。
- 英文 UI 优先评估 `Plus Jakarta Sans`，中文使用 `Noto Sans SC`；拼音和数字与正文共享字体系统，避免另造装饰字体。
- 标题靠字重和空间建立层级，不使用负字距，也不随视口宽度缩放字号。
- 卡片和面板圆角不超过 `8px`；路线节点可以使用圆形。
- 互动按钮使用 1-2px 边框和轻微底部投影，按下时产生 1-2px 位移，形成多邻国式触感但不做厚重塑料感。

### 11.4 页面布局语言

- `/learn`：中央路线是第一视觉层；今日复习和进度作为两侧或下方辅助信息，不用多个同权重卡片争抢注意力。
- 路线地图：使用单条有节奏弯曲的声调路径，当前节点最突出，已完成和锁定状态可快速扫描。
- 课程页面：最大内容宽度约 `720-800px`，顶部为退出和进度，中部为唯一学习任务，底部为稳定的检查/继续操作区。
- 移动课程：任务区占据主要首屏，操作区贴近拇指可达范围；内容增长时滚动，不让固定栏遮挡题目。
- 桌面课程：利用左右空间呈现音频、解释或上下文，但不把主要体验拆成装饰性左右卡片。
- 不使用卡片嵌套卡片；页面区段保持无框，卡片只承载答案选项、重复内容或确实需要边界的工具。

### 11.5 组件与反馈

- 路线节点：圆形图标按钮，明确显示当前、完成、锁定、复习和检查点状态。
- 答案选项：整行可点击，选中后同时使用颜色、边框、图标和文本反馈，不能只依赖颜色。
- 主命令：使用文字按钮；播放、重播、录音、关闭等熟悉工具使用 lucide 图标并提供 tooltip 或无障碍名称。
- 成功反馈：轻微上移或缩放，持续约 160-220ms；不使用持续弹跳和满屏庆祝。
- 路线推进：完成课时后以约 300ms 的曲线点亮连接到下一节点，这是主要的阶段性动效。
- 错误反馈：不震动整个页面；保持答案可见，解释原因并给出明确重试动作。
- 动画尊重 `prefers-reduced-motion`，关闭后不影响状态理解。

### 11.6 明确不照搬

- 不复制 Brilliant 或 Duolingo 的 Logo、插画、角色、文案、配色比例和具体页面布局。
- 不使用绿色主导的整站视觉，也不创建类似 Duolingo 的动物吉祥物。
- 不使用爱心体力、错误惩罚、夸张 streak 压力或儿童化拟声反馈。
- 不把 Brilliant 的克制误解成大面积空白和无情绪，也不把 Duolingo 的亲和误解成所有内容都装进圆润卡片。
- 不做深色赛博朋克、传统红金中国风或通用 SaaS Dashboard 风格。

### 11.7 响应式与无障碍原则

- 以 390px 左右手机宽度作为日常学习主场景。
- 桌面端不简单放大手机卡片，而是合理利用音频、文本和辅助信息空间。
- 固定格式控件有稳定尺寸，动态文本不引发布局跳动。
- 核心控件满足触控目标、键盘焦点和可读对比度要求。
- 在 `390x844`、`768x1024` 和 `1440x900` 三组基准视口检查路线、课程和反馈状态。
- 使用最长英文文案、汉字、拼音和错误信息验证无溢出与遮挡。
- 正确、错误、完成和锁定状态都必须具有非颜色提示。

## 12. 正式开发路线图

阶段只在退出标准满足后推进，不以“写了多少代码”判断完成。

### M0-FE：前端学习体验 Alpha，5-7 周

交付：

- 目标入口、`/learn` 路线主页和路线地图。
- Brilliant / Duolingo 融合的基础 Token、声调路线视觉签名和核心互动状态。
- 四节点 HSK 3.0 Level 1 Starter 路线。
- 拼音、对话、生词三类真实课程和检查点。
- 本地进度、错误回流和 `/review`。
- 移动/桌面/键盘验收和核心测试。

退出标准：陌生用户不需要开发者解释，可以完成整条路线并在刷新后继续学习。

详细阶段、组件边界、模拟情景和测试矩阵见[前端学习体验开发计划](12-frontend-learning-experience-development-plan.md)。M0-FE 完成前，M1 账户与内容后端阶段保持暂停。

### M1：账户与内容基础，2-3 周

交付：

- Google ID token 服务端验证。
- 用户、账号绑定、session、退出当前/全部设备。
- 访客进度合并到登录账户。
- HSK 3.0 Level 1 标准与词汇主数据导入。
- 内容校验报告和最小学习事件持久化。

退出标准：用户可以跨设备继续纵向切片；Level 1 字词可查询并能被课程稳定引用。

### M2：Starter 路线 Alpha，4-6 周

交付：

- 3-4 个入门单元，约 18-24 门短课。
- 覆盖语音、问候、个人信息、数字时间等入门任务。
- 原创或已授权的正式音频和必要图片。
- 基础 SRS、每日复习、错题本和学习进度。
- 英语界面和完整移动端体验。

退出标准：种子用户可以连续学习两周；路线、课程、复习和错题构成日常闭环。

### M3：HSK 3.0 Level 1 完整路线，8-12 周

交付：

- 覆盖一级 300 个新增词和官方一级核心任务范围。
- 按真实重复提取稳定课程模板和共享教学组件。
- 单元检查点、阶段诊断和综合复习。
- 内容审核、版权审核和占位素材发布阻断。
- 基础内容管理工具，仅维护稳定模板字段。

退出标准：用户可以从零开始完成完整 Level 1 路线；新增同类型课程主要修改内容数据。

### M4：备考闭环，4-6 周

交付：

- 入门诊断和推荐起点。
- 听力、阅读、词汇、语法专项练习。
- 原创迷你模考、计时、评分、解析和报告。
- 错题自动回流路线和复习。

退出标准：学习、练习、检查、报告和补弱形成闭环；报告能解释用户下一步为何学习某内容。

### M5：扩展与商业验证

候选工作：

- HSK 3.0 Level 2-3。
- 当前考试备考路线和 HSK 2.0 映射。
- PWA、离线复习和通知。
- 西语及一个东南亚语言。
- AI 口语评分、HSKK 练习和作文反馈。
- 订阅、地区定价和机构试点。

启动条件：M3-M4 已经证明留存和学习效果；不得以扩展功能代替修复核心学习体验。

## 14. 指标体系

### 14.1 北极星指标

每周完成至少 3 次有效学习会话的活跃学习者数量。

“有效学习会话”必须包含完成课程或复习节点，不能只打开页面。

### 14.2 产品验证指标

- 选择目标后开始第一课的比例。
- 第一课完成率。
- 首条四节点路线完成率。
- `Continue` 点击率。
- 第二天和第七天返回率。
- 到期复习完成率。
- 错题重试后的正确率。
- 单课中途退出步骤。
- 音频失败率和录音权限拒绝率。
- 移动端核心路径完成率。

### 14.3 内容质量指标

- schema 校验失败数。
- 原创内容审核通过率。
- 占位素材和版权未确认素材数量。
- 学习者报告的内容错误数。
- 单题异常高错率和异常高通过率。
- 课程步骤退出热点。

首批用户量不足时不做复杂“AI 推荐”，先根据这些可解释信号改进课程。

## 15. 质量门

每个可发布课程必须满足：

- 有明确教学目标、前置知识和完成条件。
- 正文、题目、反馈和素材元数据通过 Zod 校验。
- 所有发布内容原创、已授权或许可证兼容。
- 不包含受限占位素材。
- 音频缺失、加载失败、自动播放受阻和权限拒绝有明确状态。
- 核心互动可用键盘完成，不提前泄露答案。
- 移动端无溢出、遮挡或不可触控控件。
- 学习事件、进度和错题可关联到稳定 ID。
- 判题和完成规则有单元测试。
- 核心学习路径有浏览器回归和视觉检查。

## 16. 风险与止损规则

| 风险 | 处理 |
|---|---|
| 再次陷入平台和编辑器建设 | 任何基础设施任务必须服务于当前可见学习路径；Studio 保持冻结 |
| MVP 继续膨胀 | M0-FE 只交付四节点路线；未满足退出标准前不加词库、模考或 AI |
| 内容生产成为瓶颈 | 先建立少量高质量课和窄模板，再批量生产 |
| 教材或素材侵权 | 参考与发布内容分离，占位明确标记，发布硬阻断 |
| AI 内容质量不可控 | AI 只辅助草拟，人工语言/教学审核和相似度检查后发布 |
| 音频质量拖累体验 | Alpha 前替换占位音频；保存录制者和授权记录 |
| 登录阻挡首次价值 | M0-FE 允许访客学习并本地保存，完成价值体验后再引导登录同步 |
| 数据模型提前过度设计 | 先使用本地类型数据验证，稳定后映射数据库 |
| 游戏化掩盖学习效果 | 不使用惩罚性体力；奖励只反馈真实学习进展 |
