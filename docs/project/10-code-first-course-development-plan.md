# 代码优先课程开发与模板演进计划

> 本文是课程实现专题方案；课程在网站整体中的执行顺序以[网站整体规划与正式开发主线](11-website-master-plan.md)为准。

本文记录 HSKWise 在完成 Course Studio Phase 0-4 技术实验和 Phase U1 第一批优化后作出的课程开发方向调整。它是课程前端实现的专题主线；[Course Studio 开发计划](07-course-studio-development-plan.md)和[可用性重构实施计划](08-course-studio-usability-refactor-plan.md)保留为历史方案与技术资产清单。

| 项目 | 当前值 |
|---|---|
| 决策日期 | 2026-08-18 |
| 文档状态 | 当前执行方案 |
| 专题阶段 | CF0：冻结 Studio，整理可复用能力；整体处于 M0 |
| 课程生产方式 | 代码优先，模板后置 |
| Course Studio 状态 | 暂停通用编辑器开发 |

## 1. 决策摘要

暂停继续建设通用 Course Studio，不再优先投入自由内容画布、通用时间轴、复杂属性面板、完整中文化、编辑器历史和可视化编排体验。

新的课程开发方式是：

1. 根据具体课程类型直接编写高质量 React 课程实现。
2. 将正文、题目、素材和可变化参数与 React 渲染代码分离。
3. 连续制作几个真实课程，观察重复结构和真实差异。
4. 只对已经稳定重复的部分提取课程模板。
5. 模板稳定后，课程实例只修改类型安全的 JSON 数据。
6. 只有模板数量和使用者规模证明有必要时，才建设轻量模板编辑器。

该方向不是放弃结构化课程，而是把抽象时机从“制作课程之前”推迟到“真实课程证明重复之后”。

## 2. 调整原因

### 2.1 当前 Course Studio 的成本问题

- 通用编辑器需要同时解决信息架构、内容画布、属性系统、素材管理、时间轴、撤销重做、响应式、无障碍和持久化。
- 每一种课程效果都要求编辑器增加新的配置能力，最终接近低代码平台或简化版视频编辑器。
- 真实课程样本不足时，难以提前判断哪些能力需要通用、哪些只属于某一课程。
- 为编辑器建立抽象的时间，明显高于直接完成真实课程的时间。
- 编辑器自由度越高，课程视觉和教学质量越难统一。

### 2.2 代码优先的直接收益

- 可以围绕教学目标直接设计交互，不受通用 schema 和面板限制。
- 课程效果由 React、CSS 和测试控制，视觉与交互结果更稳定。
- 可以尽快获得真实学习者反馈，而不是继续验证编辑器本身。
- 重复结构来自实际课程，不依赖预先猜测。
- 模板成熟后仍然可以实现 JSON 驱动和批量生产。

## 3. 核心原则

### 3.1 代码优先，不等于内容全部写死

每种课程由模板代码控制结构和交互，课程事实仍放入独立数据：

```text
课程 JSON / TypeScript 数据
          ↓
课程类型模板（React）
          ↓
共享教学组件与互动组件
          ↓
学习进度、事件、音频和错题运行时
```

React 负责：

- 页面结构和视觉层级。
- 教学步骤和交互流程。
- 动画、状态切换和媒体控制。
- 针对课程类型的响应式体验。

课程数据负责：

- 标题、教学目标和讲解文本。
- 生词、例句、对话和翻译。
- 题目、选项、答案和反馈。
- 图片、音频、视频和版权信息。
- 知识点引用、HSK 等级和内容来源。

### 3.2 先实现，再抽象

- 第一个课程允许保留课程专用代码。
- 第二个同类课程开始记录重复点，但不急于建立完整模板协议。
- 第三个同类课程仍重复的结构，才进入模板候选。
- 模板不能为了覆盖假设场景而增加大量可选字段。
- 当 JSON 需要嵌入任意样式或任意脚本时，说明模板边界过宽，应拆分新模板。

### 3.3 课程质量优先于编辑自由度

- 每种模板提供受控布局，不提供任意坐标和任意图层。
- 互动步骤使用课程类型允许的固定流程或有限状态机。
- 动画使用命名预设，不建设通用时间轴编辑器。
- 课程作者修改内容数据，模板维护者修改代码与视觉行为。

## 4. 首批真实课程

选择差异足够明显的三种课程验证边界。

### 4.1 拼音与声调讲解课

核心结构：

- 学习目标。
- 发音部位或声调曲线展示。
- 教师讲解与示范音频。
- 听辨和选择题。
- 跟读练习。
- 课末检查。

需要验证的共享能力：音频播放、声调图、分步讲解、听辨互动、跟读录音和完成规则。

### 4.2 对话精读与跟读课

核心结构：

- 对话场景导入。
- 逐句播放和角色区分。
- 点击句子查看拼音、翻译和重点词。
- 语法或表达提示。
- 跟读和角色扮演。
- 内容理解题。

需要验证的共享能力：逐句音频、行级选择、词语解释、角色状态、字幕和口语练习。

### 4.3 生词学习与练习课

核心结构：

- 生词卡片。
- 汉字、拼音、释义、例句和音频。
- 识别、回忆和听音选择。
- 配对、排序或填空。
- 错词回顾。

需要验证的共享能力：词条引用、闪卡、题目生成、练习反馈、掌握状态和错题回流。

## 5. 目标代码结构

具体目录在开始实现首门课程时根据现有代码调整，职责目标如下：

```text

    course-session.ts
    learning-events.ts
    progress.ts
    audio.ts
  primitives/

    interaction-feedback.tsx
  templates/
    pinyin-lesson/
    dialogue-reading/
    vocabulary-practice/
  content/
    hsk3-level-1/
```

首批实现可以复用 `src/features/course-studio/` 中稳定的运行时；不要求立即移动文件。只有职责稳定后再重命名，避免为了新目录做无行为收益的迁移。

## 6. 模板数据协议

模板成熟后，建议由 TypeScript 工厂和 Zod schema 共同定义：

```ts
export const lesson = definePinyinLesson({
  id: 'hsk3-l1-pinyin-tones',
  title: { en: 'The four tones', zhHans: '认识四声' },
  objectives: ['distinguish-tone-shapes', 'identify-tone-by-audio'],
  steps: [
    {
      kind: 'tone-explanation',
      tone: 1,
      explanation: { en: 'Keep the pitch high and level.' },
      audioAssetId: 'tone-1-demo',
    },
    {
      kind: 'listening-check',
      prompt: { en: 'Which tone is high and level?' },
      correctTone: 1,
    },
  ],
})
```

协议约束：

- 数据必须可序列化并通过 Zod 校验。
- 内容数据不能包含 React 组件、函数、CSS class 或任意 JavaScript。
- 模板字段使用教学语言命名，不暴露 action ID、target ID 或内部事件名。
- 每个模板独立版本化，例如 `pinyinLesson/v1`。
- 模板升级需要 migration 或明确重新生成，不静默改变已发布课程。
- 模板允许有限的命名预设，不提供无限样式配置。

## 7. 现有成果处理

### 7.1 保留并复用

- `SceneDataSchema`、interaction schema 和稳定 ID 约束，可作为运行时参考或逐步缩减后的数据基础。
- `ScenePlayer` 中已经验证的播放、暂停、互动等待和音频 transport 逻辑。
- multipleChoice、matching、ordering、cloze、dictation、shortAnswer、speechRepeat 和 rolePlay 互动实现。
- `InteractionAttempt`、`SceneProgress`、learning event 和错题关联模型。
- 音频状态、跟读录音、文本规范化和判题纯函数。
- 当前 16 项运行时与互动测试。

### 7.2 暂停继续投入

- 通用 Course Studio Shell 产品化。
- 通用内容画布和组件插入系统。
- 通用时间轴编辑器及其拖动、缩放和精确属性 UI。
- 完整 Inspector、通用 JSON 编辑和可视化知识点绑定。
- 为通用编辑器继续扩展 Travels 命令层和撤销历史。
- U2-U4 可用性重构。

### 7.3 当前已完成但不再扩展的实验

- U1 第一批中文壳层和四工作模式。
- 基于 `travels@2.2.0` 的文档状态、撤销重做和本地历史恢复。
- `dnd-timeline` 轨道编辑实验。
- Mock asset library、课程大纲和模板选择器。

这些代码暂时保留，便于参考和复用；在首批真实课程稳定前不进行删除或大规模重构。

## 8. 分阶段执行

### CF0：冻结 Studio 与能力盘点

预计：1 个工程日。

- [x] 记录代码优先方向决策。
- [x] 暂停 Phase U2-U4 和通用编辑器扩展。

- [ ] 确定首门课程 URL、数据入口和素材清单。

退出标准：后续任务不再以“完善 Studio”为目标，首门课程有明确教学目标和真实内容。

### CF1：完成首门拼音课程

预计：3-5 个工程日。

- [ ] 直接实现拼音/声调课程页面。
- [ ] 分离课程内容数据和 React 模板代码。
- [ ] 接入真实或可替换的音频素材。
- [ ] 完成讲解、听辨、跟读和课末检查。
- [ ] 接入学习事件、进度和错题记录。
- [ ] 完成桌面、移动端和键盘操作验收。

退出标准：学习者能完整学完课程，课程效果不依赖 Course Studio。

### CF2：完成对话与生词课程

预计：6-10 个工程日。

- [ ] 实现对话精读与跟读课程。
- [ ] 实现生词学习与练习课程。
- [ ] 记录三类课程中的公共组件和差异点。
- [ ] 保持内容数据可序列化和可校验。
- [ ] 为三类课程建立视觉和交互回归。

退出标准：三类代表性课程形成可比较样本，不通过扩展一个万能配置对象解决差异。

### CF3：提取共享组件与课程模板

预计：4-6 个工程日。

- [ ] 提取真正重复的 lesson shell、步骤导航、反馈、媒体和进度组件。
- [ ] 为每种课程建立独立 Zod schema 和 `define*Lesson` 工厂。
- [ ] 将至少两个同类课程实例迁移到模板数据。
- [ ] 建立模板版本和 migration 规则。
- [ ] 检查模板 JSON 是否仍包含代码或样式泄漏。

退出标准：新增同类课程主要修改内容数据，不需要复制整套 React 页面。

### CF4：评估轻量课程工具

不预设开发日期。

只有同时满足以下条件才启动：

- 至少三种稳定课程模板。
- 每种模板已有多个真实课程实例。
- 非开发人员确实需要频繁修改内容。
- JSON 手工维护已经成为明确瓶颈。

若启动，工具只负责模板选择、字段表单、素材选择、预览和校验，不提供自由画布或通用时间轴。

## 9. 质量门

每门真实课程至少满足：

- 明确的教学目标和完成条件。
- 不依赖开发者解释即可开始学习。
- 正文、题目和反馈均来自可校验数据。
- 音频缺失、加载失败和权限拒绝有明确状态。
- 桌面和移动端无溢出、遮挡和不可操作控件。
- 键盘可以完成核心互动。
- 互动提交不会提前泄露答案。
- 学习事件、进度和错题可以稳定关联课程步骤。
- 内容来源和版权状态可追溯。
- 单元测试覆盖判题和完成规则，浏览器测试覆盖核心学习路径。

## 10. 防止重新走向通用编辑器

出现以下信号时应停止扩展当前模板并重新划分边界：

- 配置出现任意坐标、任意 CSS、任意事件或任意表达式。
- 单个模板包含大量只被一个课程使用的可选字段。
- 为支持一个新课程而要求所有旧课程迁移大量无关字段。
- JSON 已经比等价 React 代码更难理解和调试。
- 课程效果需要通过多层通用 action 才能表达简单教学步骤。

正确处理通常是新建一个更具体的模板，而不是继续扩大万能模板。

## 11. 当前进度结论

- Course Studio Phase 0-4 完成了 schema、播放器、互动、音频、事件、进度和时间轴技术验证。
- Phase U1 第一批完成了中文壳层、工作模式和 Travels 历史实验。
- 实测证明继续完成通用 Studio 需要过高投入，U2-U4 暂停。
- 当前开发重心转为 CF0-CF1：盘点可复用运行时，并完成第一门真实拼音课程。
- Phase 5 原“模板和效率工具”不再按旧计划解冻；模板能力改由 CF3 从真实课程中提取。
