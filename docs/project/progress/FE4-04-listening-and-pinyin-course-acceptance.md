## 1. 本次结论

`/lessons/four-tones` 已形成“观察 -> 音高方向 -> 图形识别 -> 三组听辨 -> 跟读 -> 五题检查 -> 总结”的完整拼音课程。听辨答案在音频结束前不可操作，音频失败可切换为明确的视觉替代路径；课末检查必须逐题答对，错误会写入现有错题和复习队列。

本阶段按 Frontend Learning Alpha 的占位素材政策完成。新增发音仍是带强制替换标记的本地 TTS，不宣称为原创真人录音；真人普通话素材继续作为发布前硬性门禁。

## 2. 课程协议与复用边界

- `pinyinLesson/v1` 新增 `tone-listening-choice` 和 `lesson-check` 两种拼音专用步骤。
- 听辨步骤包含音频引用、候选声调、正确答案、反馈和知识点引用。
- `lesson-check` 固定包含五道拼音题，每题有独立稳定 ID 和知识点引用。
- Schema 校验候选项唯一、正确答案必须在候选项中、课末题 ID 唯一。
- 共享 Lesson Runtime 只接收 interaction 完成规则，不理解音频波形、声调选项或五题内部进度。
- 第二份未发布 fixture 已通过 schema、运行时投影和两个新组件的静态渲染测试。

## 3. 听辨交互

- 新增三组单声调听辨，分别验证第一声、第三声和第四声。
- 播放结束前选项保持禁用，界面不展示拼音例词和声调曲线。
- 播放时使用窄波形作为语音导视焦点，并提供重播能力。
- 音频加载失败或播放受阻时显示告警，用户可显式进入声调曲线视觉替代路径。
- 答错后由共享底部反馈和 Try again 处理，同时把知识点写入复习队列。

## 4. 五题课末检查

- 五段进度刻度显示当前题号，不把五题展开成五个共享运行时步骤。
- 每题即时显示正确或错误反馈；错误状态不能推进到下一题。
- 五题全部答对后才向 Lesson Runtime 提交一次完成 attempt 并解锁 Continue。
- 课末错误按题目知识点写入全局 mistake / review store，同知识点继续沿用去重规则。
- 纯 reducer 管理题号、选择、反馈和答案序列，React hook 只聚合交互和外部副作用。

## 5. 素材与版权

- 三段音频由 macOS `Tingting` TTS 在项目内生成，未读取或复制 `docs/textbooks` 内容。
- 课程数据、MP3 metadata 和[占位素材清单](/Users/yanglong/Documents/YL/hskwise/public/audio/placeholders/pinyin/README.md)均标记发布前必须替换。
- 替换真人录音时保持相同 sample ID 和课程协议，不需要修改交互组件。
